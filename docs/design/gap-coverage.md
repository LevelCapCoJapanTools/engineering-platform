# 機能ギャップ対応表

[機能ギャップ調査](../reserch/gap-analysis-vse-iso29110.md)（2026-11-28）の各項目について、画面モックのどこで扱っているかを示す。画面の詳細は [デザイン依頼書](design-request.md) 第6章、実装方針は [SSOT](../SSOT.md) を正本とする。

## 集計

画面モックは143画面（開発用を除く）。2026-11-28 の対応で、新規に56画面を追加（87画面から143画面へ）し、既存画面の大半を経営層が閲覧・判断する前提に改訂した。全画面・全状態（655状態）をブラウザで巡回し、実行時エラー、空表示、リンク切れ、幅390pxでの横はみ出しがないことを確認した。

## 読み方

- 「画面」は `apps/web` の画面モックの画面ID。`npm run dev` のあと `#/screens` から開ける
- 画面モックは表示専用で、架空のサンプルデータで動く。画面があることは、その機能の本番実装（実データ、外部サービス接続、権限、永続化）を意味しない（調査 2.3）
- 「本番実装の前提」は、実装前に SSOT で確定が必要な判断（調査 第9章、SSOT 第13章）を指す

## 4.13 SaaS、セキュリティ、可用性

画面で扱う部分は、稼働状況と障害告知（P-10）、サポートと脆弱性の受付（P-11）、保守表示（Z-04）、セキュリティ設定（S-06）、データの保存地域（S-05、S-04）に限る。マルチテナント分離、暗号化、バックアップ、監視、侵入評価などは本番インフラの設計事項で、SSOT 第13章「本番インフラ」で扱う。

## 第5章 コネクタ共通設計

アーキテクチャ境界（`crates/platform`、`crates/server`、`crates/worker`）と概念モデル（`ConnectorInstallation`、`ExternalEvent`、`Notification`、`OnCallTarget`、`Incident`、`EvidenceManifest`）は、画面モックの型（`apps/web/src/lib/types.ts`）で表示に必要な項目だけを先に定義している。サーバー側の実装は、SSOT 第13章の判断を確定してから行う。
