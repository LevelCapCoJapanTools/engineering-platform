# 追補の対応表（発注企業・受注側JV・フリーエンジニア）

[発注企業・受注側JV・フリーエンジニアをつなぐ開発サービスの追加・修正案](../reserch/executive-freelancer-service-proposal.md)（2026-11-28）の改修60件について、画面モックと実装の対応を示す。範囲と設計判断は [SSOT](../SSOT.md)（第1・2章と第13章の追補）、画面の詳細は [デザイン依頼書](design-request.md) 第6章を正本とする。

## 集計

改修60件のすべてを画面モックのどこかで扱った。画面は143画面から197画面になった（新規54画面、既存の画面のうち顧客ポータル、リリース、スケジュール、通知、権限、AI 設定などを改訂）。全197画面・978状態をブラウザで巡回し、実行時エラー、空表示、リンク切れ（380件を確認）、幅390pxでの横はみ出しがないことを確認した。あわせて、顧客ポータルとフリーエンジニアの21画面・125状態で、JV内部予算、委託費、粗利、他の受託者の氏名・報酬が本文に出ないことを検査した。

取引ドメインの中核（12件）は `crates/platform` に実装し、単体テストと PostgreSQL 統合テストで確認した。外部サービス（電子契約、Apple、チャット、CI/CD、メール）への実際の接続と、利用者の認証は未実装で、SSOT 第13章の判断に沿って次の段階で実装する。

## 読み方

- 「画面」は `apps/web` の画面モックの画面ID。`npm run dev` のあと `#/screens` から開ける。画面モックは架空のデータで動き、API に接続しない
- 「実装」は `crates/platform` に実装し、単体テストと PostgreSQL 統合テストで確認した範囲（`trade`、`disclosure`、`outbound`、`deploy`）。HTTP の公開エンドポイントは、利用者の認証を実装するまで追加しない
- 画面があることは、外部サービス（電子契約、Apple、チャット、CI/CD 等）への実際の接続を意味しない
